# 安全加固规格

## 新增需求

### 需求：所有响应包含安全头
系统应在所有 HTTP 响应中包含安全头。

#### 场景：响应头
- **当** 发送任何 HTTP 响应
- **则** 响应包含：
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-XSS-Protection: 1; mode=block`
  - `Content-Security-Policy: default-src 'self'; img-src * data:; style-src 'self' 'unsafe-inline'`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: geolocation=(), microphone=(), camera=()`

### 需求：CSRF 令牌保护
系统应对所有状态变更请求验证 CSRF 令牌。

#### 场景：CSRF 令牌生成
- **当** 用户成功登录
- **则** 服务器生成 CSRF 令牌
- **且** 在 cookie 中设置 CSRF 令牌（HttpOnly=false，可被 JS 读取）
- **且** 在响应体中返回 CSRF 令牌

#### 场景：CSRF 令牌验证
- **当** 客户端发起 POST/PUT/DELETE/PATCH 请求
- **则** 客户端包含 `X-CSRF-Token` 请求头
- **且** 服务器验证请求头与 cookie 值匹配
- **且** 不匹配返回 403 及 `CSRF_TOKEN_MISMATCH` 错误

#### 场景：CSRF 令牌轮换
- **当** 访问令牌被刷新
- **则** 生成并返回新的 CSRF 令牌

### 需求：RSS 内容清理
系统应清理来自 RSS 订阅源的所有 HTML 内容。

#### 场景：文章内容清理
- **当** RSS 订阅源文章包含 HTML 内容
- **则** 内容在存储或显示前使用 UGC 策略清理
- **且** 允许的标签：p、br、a、img、ul、ol、li、blockquote、pre、code、strong、em、h1-h6
- **且** 移除所有 script 标签、onclick 属性和 javascript: URL

#### 场景：订阅源元数据清理
- **当** 解析订阅源 title 或 description
- **则** 内容使用严格策略清理（仅文本，无 HTML）

### 需求：订阅源 URL SSRF 防护
系统应验证并限制订阅源 URL 获取。

#### 场景：URL 协议验证
- **当** 用户添加新订阅源 URL
- **则** 仅允许 http:// 和 https:// 协议
- **且** 其他协议返回 400 错误

#### 场景：私有 IP 阻止
- **当** 解析订阅源 URL
- **则** 系统阻止以下范围的 IP：
  - 10.0.0.0/8（私有）
  - 172.16.0.0/12（私有）
  - 192.168.0.0/16（私有）
  - 127.0.0.0/8（回环）
  - 169.254.0.0/16（链路本地/AWS 元数据）
  - ::1/128（IPv6 回环）
  - fc00::/7（IPv6 私有）
- **且** 被阻止的 URL 返回 400 及 `URL_NOT_ALLOWED` 错误

### 需求：订阅源大小限制
系统应对订阅源内容强制执行大小限制。

#### 场景：订阅源获取超时
- **当** 获取订阅源 URL
- **则** 请求在 30 秒后超时
- **且** 超时作为订阅源获取失败记录日志

#### 场景：文章数量限制
- **当** 解析 RSS 订阅源
- **则** 仅处理前 1000 篇文章
- **且** 超出文章记录日志但不存储

#### 场景：内容大小限制
- **当** 单篇文章内容超过 1MB
- **则** 内容被截断并添加标记 `[truncated]`
- **且** 记录原始大小日志

### 需求：密码安全
系统应强制执行安全的密码处理。

#### 场景：密码复杂度
- **当** 用户注册或更改密码
- **则** 密码必须至少 8 个字符
- **且** bcrypt cost 因子为 12 或更高

#### 场景：密码哈希
- **当** 存储密码
- **则** 密码使用 bcrypt 哈希
- **且** 明文密码永不记录日志

### 需求：JWT 签名安全
系统应使用安全的 JWT 签名配置。

#### 场景：签名算法
- **当** 生成 JWT
- **则** 使用 HS256 算法（或生产环境使用 RS256）
- **且** 密钥至少 256 位（32 字节）

#### 场景：令牌声明
- **当** 生成访问令牌
- **则** 声明包含：sub (user_id)、exp、iat、csrf_token
- **且** 声明不包含敏感数据（password、email）

### 需求：速率限制键组合
系统应使用组合键进行已认证速率限制。

#### 场景：未认证速率限制
- **当** 请求无有效访问令牌
- **则** 速率限制键为客户端 IP 地址

#### 场景：已认证速率限制
- **当** 请求有有效访问令牌
- **则** 速率限制键为 IP + user_id 的组合
- **且** 这防止单个受损账户使用全部配额

### 需求：依赖漏洞扫描
系统应检测有漏洞的依赖。

#### 场景：CI 漏洞检查
- **当** CI 管道运行
- **则** `govulncheck` 扫描 Go 依赖
- **且** `npm audit` 扫描前端依赖
- **且** 高/严重漏洞导致管道失败
